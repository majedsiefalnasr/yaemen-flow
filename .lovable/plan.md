### المرحلة 2 — إعادة بناء نموذج التاجر

**ملفات:** `src/lib/mock.ts` (نوع `Merchant` + البذور), `src/routes/merchants.tsx`, ملفات جديدة `src/routes/merchants.new.tsx` و `src/routes/merchants.$id.edit.tsx`.

تحديث نوع `Merchant`:
```ts
type OwnerShare = { name: string; percent: number };
type LinkedCompany = { name: string; sector: string };
type Merchant = {
  id: string;
  tax: string;                  // PK
  name: string;
  taxCardExpiry: string;        // ISO date
  cr: string;
  crExpiry: string;             // ISO date
  owners: OwnerShare[];         // ≥25% فقط
  companies: LinkedCompany[];   // واحدة أو أكثر
  status: "active" | "suspended";
  entityId: string;             // البنك التابع
  transactions: number;
};
```

- حذف `address`, `contact`, `category` من المستوى الرئيسي للتاجر.
- صفحات إضافة/تعديل مستقلة (وليست Dialog)، مع Repeater للملاك (اسم + نسبة%، التحقق أن كل عنصر ≥25) و Repeater للشركات (اسم + قطاع).
- DatePickers لتاريخي انتهاء البطاقة والسجل.
- صلاحيات الإنشاء/التعديل تُمنح لـ: `data_entry`, `internal_reviewer`, `bank_admin`.
- ترحيل البذور القديمة بقيم افتراضية معقولة لتجنّب كسر الشاشات.

### المرحلة 3 — إعادة بناء شاشة الطلب بخمسة تبويبات

**ملفات:** `src/routes/requests.new.tsx`, `src/routes/requests.$id.tsx`, `src/lib/mock.ts` (نوع `RequestRow`), `src/lib/governance.ts`.

توحيد التبويبات الخمسة في وضع الإنشاء/التعديل/العرض/المراجعة/التصويت:
1. **المعلومات الأساسية** — البحث بالرقم الضريبي يجلب التاجر تلقائياً (`tax → merchant`)، يعرض/يسمح بتعديل النسخة المحلية فقط داخل الطلب (snapshot على `RequestRow`)، اختيار شركة واحدة من شركات التاجر.
2. **بيانات الفاتورة** — جميع الحقول والقوائم المنسدلة كما هي محددة، مع منطق:
   - `paymentTerm === "كلي"` ⇒ `requestPercent = 100` ومقفل.
   - `paymentTerm === "جزئي"` ⇒ `5 ≤ requestPercent < 100`.
   - تحقق التكرار: على مستوى المنظومة، إذا وُجد طلب بنفس (الرقم الضريبي + رقم الفاتورة) ونسبته 100% أو مجموع النسب سيتجاوز 100% ⇒ منع الحفظ (toast واضح).
3. **بيانات الشحن** — مع القوائم المنسدلة الموثّقة (موانئ، Incoterms).
4. **الوثائق المطلوبة** — قائمة الـ 14 وثيقة، تمييز الإجباري، استخدام `local-files.ts` الحالية للرفع.
5. **سير العملية التنظيمية** — Stepper يعرض المراحل حسب جهة المستخدم:
   - بنك تجاري: مسودة → مراجعة داخلية → مراجعة اللجنة الوطنية → سويفت → تأكيد مصارفة → مكتمل.
   - اللجنة: مراجعة اللجنة المساندة → تصويت اللجنة التنفيذية → إصدار تأكيد مصارفة → مكتمل.

تحديث نوع `RequestRow` لإضافة جميع الحقول الجديدة (مع الإبقاء على الحقول الحالية المتوافقة وحذف غير المتوافق منها).

- التخزين الحالي `governance.ts` يستخدم `cells` في الذاكرة + localStorage — سنبقيه كما هو، فقط نوسّع الأنواع وندخل migrations بسيطة عند قراءة البذور.

- ترتيب القوائم المنسدلة (currencies, ports, incoterms, invoice types, request types …) ستُستخرج إلى ثوابت في `src/lib/mock.ts` لإعادة الاستخدام.

### أسئلة تأكيدية قبل البدء

1. هل تريد تنفيذ كل المراحل دفعة واحدة في رد واحد كبير، أم نقسّمها على عدة ردود (مرحلة–مرحلتين في كل رد) لسهولة المراجعة؟
2. هل أحتفظ بصفحة "نموذج طلب وثيقة التأكيد" في شاشة الطلب كما هي (تأكيد المصارفة الخارجية)، أم تريد تعديلها كذلك؟
3. هل تحتفظ ببذور الطلبات الحالية (مع ترحيلها لتتطابق مع الحقول الجديدة قدر الإمكان)، أم نمسحها ونزرع بيانات جديدة مطابقة للنموذج الجديد بالكامل؟
